# Sovereign Account — Documentation Site

Static site generator for the Sovereign Account documentation. Compiles Markdown sources under `../domain/account/` and the C4 model under `../architecture/` into HTML, JSON, Mermaid, and LLM-oriented artifacts, ready to publish to any static host.

A human-readable domain (`docs.sovereign-account.dev` or similar) is planned but not yet in place. See "Decentralized naming" below.

## Stack

- **Astro 7** — static site generation with Content Collections and Zod validation
- **Tailwind CSS v4** — styling, dark mode, responsive layout
- **Bun** — package manager and script runner
- **Structurizr** — C4 model rendering (interactive viewer + Mermaid export)
- **Irys** — permanent storage target (devnet for tests, mainnet for production)

## Development

```sh
bun install
bun run dev
```

`dev` runs the sync, exports the C4 diagrams, then starts the Astro dev server at `http://localhost:4321`. Edits to `../domain/account/*.md` or `../architecture/workspace.dsl` require restarting the dev server (the sync and export are one-shot).

## Build

```sh
bun run build
```

The build pipeline:

1. `build-architecture.ts` runs Structurizr CLI in Docker to export the static viewer (`architecture/static/`) and the Mermaid sources (`architecture/mermaid/`). Rewrites absolute asset paths to relative and neutralizes the introduction modal without freezing the viewer.
2. `expand-architecture.ts` replaces `<!-- architecture:start X -->` markers in the markdown with the corresponding Mermaid blocks. Markdown sources stay readable on GitHub (native Mermaid rendering) and become interactive in Astro (rehype plugin swap).
3. `sync-content.ts` copies `../domain/account/` into `src/content/docs/` and `public/`, rewrites all `.md` links to absolute lowercase routes, and lowercases filenames.
4. `validate-frontmatter.ts` rejects any `.md` missing required frontmatter.
5. `astro build` generates HTML into `dist/`. The markdown processor applies two rehype plugins:
   - `rehype-architecture.ts` — swaps `%% kipio-diagram: X` Mermaid blocks for an interactive embed (title, open-full-size link, iframe, interaction hints).
   - `rehype-responsive-tables.ts` — wraps every `<table>` in a horizontal scroll container.
6. `make-relative.ts` converts absolute asset and route paths to relative paths, so the site works under any origin-isolated host. The `architecture/` directory is skipped: its output is self-contained.
7. `generate-data.ts` emits one JSON per document at `dist/_data/<chapter>/<slug>.json`, plus `dist/_data/manifest.json`.
8. `generate-llms.ts` emits `dist/llms.txt` indexing all content docs.

Final output:

```text
dist/
├── index.html
├── ubiquitous-language/<slug>/index.html   # rendered HTML
├── ubiquitous-language/<slug>.md           # raw markdown for LLMs
├── formal-laws/<slug>/index.html
├── formal-laws/<slug>.md
├── _data/<chapter>/<slug>.json             # structured frontmatter
├── _data/manifest.json
├── architecture/                           # Structurizr static viewer + Mermaid
│   ├── index.html
│   ├── css/
│   ├── js/
│   ├── workspace.js
│   └── mermaid/
├── assets/                                 # CSS bundle
└── llms.txt
```

## Architecture Diagrams

The C4 model lives in `architecture/workspace.dsl` at the repository root. It is rendered to:

1. **An interactive static site** embedded via iframe in the documentation pages.
2. **Mermaid sources** rendered natively on GitHub.

Both are produced by the same script (`build-architecture.ts`), so the two views never diverge.

### Preview locally

```sh
cd site
bun run arch:preview
```

Opens Structurizr Lite at `http://localhost:8080`, watching `workspace.dsl` for changes.

### Export for the site

```sh
bun run architecture
```

Runs Structurizr CLI in Docker, exports `static/` and `mermaid/`, post-processes them (path rewriting + modal suppression), and copies the results to `site/public/architecture/`. The `build` pipeline invokes this automatically.

### Requirements

- **Docker** (for Structurizr Lite and CLI)

### How the markdown stays portable

The markdown sources use HTML comment markers that do not render anywhere:

```markdown
### Foundation

<!-- architecture:start Foundation -->
<!-- architecture:end -->
```

`expand-architecture.ts` fills the markers with a Mermaid code block prefixed by `%% kipio-diagram: Foundation`. That prefix:

- Is invisible when GitHub renders the Mermaid diagram.
- Is consumed by `rehype-architecture.ts` in Astro to build the embed wrapper.

Result: one markdown file that renders well on GitHub and interactively on the published site, with no manual duplication.

### Embed block anatomy

Each diagram renders as:

```text
┌─────────────────────────────────────────────┐
│ Foundation — Domain Primitives  Open full ↗ │
├─────────────────────────────────────────────┤
│              [iframe: viewer]               │
├─────────────────────────────────────────────┤
│ Click elements to drill down · Double-click │
│ background to zoom out · Drag to pan ·      │
│ Scroll to zoom · [i] for the diagram key    │
└─────────────────────────────────────────────┘
```

The "Open full size" link points to `/architecture/?diagram=X` for a distraction-free view.

### URL contract

Iframe URLs use the form `/architecture/?diagram=<Name>&introduction=false`. The trailing slash is required: static hosts like `serve` 301-redirect `/path/index.html` to `/path` (dropping the trailing slash), and without it, relative asset paths inside the viewer resolve against `/` instead of `/architecture/`, causing 404s for `css/`, `js/`, and `workspace.js`.

## Deployment Playbook

Everything below is a pitfall we actually hit while getting this site to render correctly on Irys's CDN. Most apply to any static host without server-side directory resolution.

### 1. Astro 5 removed `entry.render()`

**Symptom:** `TypeError: entry.render is not a function` at build.

**Cause:** Astro 4 exposed `render` as a method on the entry. Astro 5 moved it to a top-level function.

**Fix:**

```ts
import { getCollection, render } from 'astro:content';
const { Content, headings } = await render(entry);
```

### 2. Astro 7 defaults to Sätteri, not unified

**Symptom:** After adding `remarkPlugins` to `markdown`, the build fails with "unified processor is no longer installed by default".

**Cause:** Astro 7 switched the default Markdown processor to Sätteri. Remark plugins require the `unified` processor, no longer bundled.

**Fix:**

```sh
bun add @astrojs/markdown-remark
```

```ts
import { unified } from '@astrojs/markdown-remark';

export default defineConfig({
  markdown: {
    processor: unified({ remarkPlugins: [ /* ... */ ] }),
  },
});
```

### 3. Astro ignores `_`-prefixed directories in `pages/`

**Symptom:** An endpoint at `src/pages/_data/[...slug].json.ts` never runs.

**Cause:** Astro treats any file or folder starting with `_` inside `pages/` as private and skips it. It is a Jekyll-era convention.

**Fix:** Generate those files outside Astro's routing. `generate-data.ts` writes directly to `dist/_data/` after `astro build`.

### 4. `<base href="/">` does not work with path-absolute URLs

**Symptom:** After adding `<base>` and rewriting all hrefs to absolute paths (`/assets/...`), the CDN still serves 404s.

**Cause:** Per the HTML spec, `<base href="/foo/">` only affects relative URLs. Path-absolute URLs (`/bar.css`) always resolve against the origin, ignoring `<base>` entirely.

**Fix:** Do not use `<base>`. Instead, rewrite all internal links and asset references to relative paths after `astro build`. See `scripts/make-relative.ts`.

### 5. `/` and `/_astro/` are unreliable on Irys

**Symptom:** CSS 404s on the Irys CDN with `Unable to find specified path in manifest`.

**Cause:** Irys treats `_`-prefixed paths specially and expects `assets/` at the root of the manifest.

**Fix:**

```ts
// astro.config.mjs
build: {
  format: 'directory',
  assets: 'assets',   // emits to /assets/ instead of /_astro/
},
```

Every internal link must end with a trailing slash. The CDN does not resolve `/foo` to `/foo/index.html`. It only serves `/foo/`.

### 6. Rewrite markdown links once, at sync time

**Symptom:** Cross-references in the rendered HTML point to `/page.md` or resolve incorrectly on the CDN.

**Cause:** Astro's markdown link handling behaves differently in dev versus build, and differently across hosts.

**Fix:** Rewrite all markdown links to absolute, lowercase, trailing-slash routes **before** Astro sees them, in `scripts/sync-content.ts`:

```text
[Foundations](01-foundations.md)
  → [Foundations](/ubiquitous-language/01-foundations/)
```

The relative-path pass (`make-relative.ts`) then converts those absolute paths to relative at the HTML level.

### 7. Astro lowercases content IDs, so raw file names must match

**Symptom:** "View raw" links work for `ubiquitous-language/01-foundations.md` but 404 for `formal-laws/D1-delegation-and-authority.md`.

**Cause:** Astro slugifies content IDs to lowercase (`entry.id === 'd1-delegation-and-authority'`), but the raw `.md` copies kept their original case.

**Fix:** Lowercase every filename when copying to `public/`.

### 8. Zod schema silently drops entries

**Symptom:** `index.md` files exist but no `/formal-laws/index.html` is generated.

**Cause:** The Zod schema required `chapter` and `chapter-number` on every entry. `index.md` files lack those fields and are silently filtered out.

**Fix:** Make the fields optional and enforce them with `.refine()` only on non-index entries, and in `[...slug].astro`, map the index entry to its chapter root.

### 9. Cache by path, not by manifest

**Symptom:** After deploying a new manifest, the CDN serves stale HTML.

**Cause:** The Irys CDN (`*.datasprite-cdn.com`) caches responses by URL path, not by manifest ID.

**Fix:** Rebuild clean so asset hashes change. The new hash invalidates the CSS reference and forces the CDN to fetch fresh HTML. If it persists, open in incognito.

### 10. Irys gas race on Arbitrum

**Symptom:** `max fee per gas less than block base fee` when funding the Irys account.

**Cause:** `irys.fund()` computes `maxFeePerGas` from the current `baseFee` without headroom. Arbitrum recalculates `baseFee` per block, and by the time the transaction reaches the mempool the base fee has risen.

**Fix:** Pass a fee multiplier to `fund()` and retry on race errors with progressive multipliers (1.5, 2.0, 3.0).

### 11. BigNumber.js vs bigint in the Irys SDK

**Symptom:** `price.sub is not a function` when comparing balances.

**Cause:** The Irys SDK returns values as `BigNumber`, `bigint`, `string`, or `number` depending on the version and call.

**Fix:** Normalize every value to `bigint` on receipt via a `toBigInt` helper.

### 12. `/mutable/` does not resolve `indexFile` on folder manifests

**Symptom:** `gateway.irys.xyz/mutable/<folderRootId>/` returns the raw manifest JSON, not the rendered `index.html`.

**Cause:** The `/mutable/:txId` endpoint serves the transaction content as-is. Unlike `gateway.irys.xyz/:manifestId`, it does not resolve `indexFile` for folder manifests.

**Fix:** Upload a separate **redirect HTML** as an individual transaction with `Content-Type: text/html`, tagged `Root-TX`. The mutable URL then serves that redirect, which forwards the browser to the current manifest.

See "Mutability and the redirect chain" below.

### 13. Rebuild clean before any deploy

**Symptom:** Deploy uploads stale content, or the site renders without CSS on Irys but works locally.

**Cause:** Running `bun run clean` from inside `dist/` does not clear the directory. `rm -rf dist` resolves to `dist/dist`, which doesn't exist. Astro may also refuse to wipe its own `outDir` when the current working directory is inside it.

**Fix:** Always run build commands from `site/`, never from `site/dist/`. Use `bun run clean:full`, which also wipes `node_modules/.astro` and `node_modules/.vite`.

```sh
cd site
bun run build:fresh
```

### 14. Structurizr static viewer 404s when embedded

**Symptom:** The embedded viewer 404s on `/css/`, `/js/`, and `/workspace.js`.

**Cause:** Structurizr exports its `index.html` with absolute paths (`/css/...`). Inside an iframe served from a nested route like `/formal-laws/d1-.../`, those paths resolve against the origin, not against `/architecture/`.

**Fix:** `build-architecture.ts` rewrites absolute paths to relative (`./css/...`) in the exported `index.html`. Combined with the iframe URL using a trailing slash (`/architecture/?diagram=X`), the browser's base path stays correct.

### 15. Structurizr introduction modal cannot be disabled via parameter alone

**Symptom:** The viewer shows the introduction modal on every load even with `introduction=false`.

**Cause:** The `structurizr.introduction` workspace property and the `?introduction=false` parameter are documented but do not reliably suppress the modal when the viewer is embedded in a nested iframe. Static hosts also drop query strings across directory redirects.

**Fix:** `build-architecture.ts` injects an unconditional suppression snippet into the exported `index.html`: a marker attribute, a CSS rule that hides modal-like elements, and a small burst of `setTimeout` calls that run `nuke()` over the first ~4 seconds. A continuous `MutationObserver` is intentionally avoided: the viewer mutates the DOM thousands of times per second during layout, and a global observer tanks performance.

## Mutability and the redirect chain

Irys is immutable by design. Every `uploadFolder()` produces a new `manifestId`, and every `manifestId` is a different permanent URL. For a documentation site that changes over time, sharing a link means the link points to a stale version.

Irys supports a **mutable reference** built on the `Root-TX` tag:

```text
Root-TX: <baseTxId>
```

Any subsequent transaction tagged with `Root-TX` joins the chain. The endpoint `gateway.irys.xyz/mutable/<baseTxId>/` always resolves to the most recent transaction in the chain, by millisecond-precise timestamp. All updates must be signed by the same wallet that created the base transaction.

### The folder manifest limitation

`uploadFolder()` accepts an `indexFile` parameter that instructs the gateway to serve a specific file when accessing `gateway.irys.xyz/:manifestId`. **This resolution does not apply to `/mutable/:txId`.** The mutable endpoint treats the transaction as an opaque blob, so a folder manifest returns its JSON descriptor instead of the `index.html`.

### The workaround: a second, separate chain

We maintain two chains on Irys:

1. **Folder chain** (`folderRootId`): built with `uploadFolder()` + `manifestTags: [{ Root-TX: folderRootId }]`. Not directly usable as a public URL, but preserved for the day the gateway supports `indexFile` on mutable endpoints.
2. **Redirect chain** (`redirectRootId`): built with `upload(<html>, { tags: [{ 'Content-Type': 'text/html' }, { 'Root-TX': redirectRootId }] })`. This is the intended public URL.

Flow:

```text
deploy
  │
  ├── uploadFolder(dist) ──────────────→ manifestId (per-deploy content)
  │
  ├── generate redirect.html ──────────→ points to manifestId
  │
  └── upload(redirect.html, Root-TX) ──→ txId

Public URL: https://gateway.irys.xyz/mutable/<redirectRootId>/
             ↓ serves the latest redirect
             ↓ JS window.location.replace() + <noscript> meta refresh
             https://gateway.irys.xyz/<manifestId>/
```

The redirect uses `window.location.replace()` for an immediate JS redirect, with a `<meta http-equiv="refresh">` inside `<noscript>` as fallback for JS-disabled clients.

### Current gateway limitation

The `Root-TX` chain for individual transactions (both the standalone HTML and the mutable redirect) is not reliably propagated by the gateway at this time, on devnet or mainnet. The transaction is accepted on-chain and the chain is well-formed, but the gateway may return `404` when resolving `gateway.irys.xyz/mutable/<rootId>/` or even `gateway.irys.xyz/<redirectTxId>` directly.

Until the gateway stabilizes, the recommended public URL is the per-deploy content URL (`gateway.irys.xyz/<manifestId>/`). The mutable URL is preserved for the day it resolves; the folder chain and redirect chain are both intact on-chain and will remain valid.

### CDN domains vs gateway

Every Irys upload produces two URLs:

- **Gateway**: `https://gateway.irys.xyz/<id>/`
- **CDN subdomain**: `https://<sandbox>.<node>.datasprite-cdn.com/<id>/`

**Always link to the gateway, not the CDN subdomain.** The Irys documentation explicitly warns:

> Always use `gateway.irys.xyz/<transaction-id>` to link to content. Never link directly to CDN domains — they may be rotated or replaced at any time.

The gateway routes automatically to a healthy CDN domain. Direct CDN subdomain links may break without notice.

### Custom domains

Irys does not currently offer user-configurable custom domains. The domains Irys operates are listed at `irys.xyz/security`:

- `irys.xyz`, `docs.irys.xyz`, `uploader.irys.xyz`, `gateway.irys.xyz`
- `node1.irys.xyz`, `node2.irys.xyz`, `devnet.irys.xyz`
- `datasprite-cdn.com` (CDN infrastructure)

None are assignable to user content. For a branded URL, the mapping has to live outside Irys.

### Decentralized naming

A branded, decentralized URL (`docs.<project>.ar.io`, `<project>.eth`, `<project>.hns`) is planned but not yet in place. None of the current naming systems resolve natively to an Irys manifest. The viable strategies are:

1. **Reverse proxy**: run an `ar.io` gateway (or `hsd` for Handshake) and configure Nginx to `proxy_pass` to `gateway.irys.xyz/<manifestId>/`. The domain resolves via the decentralized resolver, the content is served from Irys.
2. **ArNS on Arweave**: upload a small redirect HTML to Arweave and register an ArNS name that points to it. The name resolves to Arweave, the HTML redirects to Irys.
3. **DNS + CNAME**: a traditional DNS domain with a CNAME to `gateway.irys.xyz`. Not decentralized, but simple and works today.

### Mainnet migration

The pipeline is identical on devnet and mainnet. The network flag and RPC endpoint are the only differences, both configured in `.env`. Recommended sequence:

1. `bun run test:mutability` — verify the `Root-TX` chain on devnet with a small string.
2. `bun run test:mutable-html` — verify `Content-Type: text/html` survives the chain.
3. `bun run deploy:devnet:mutable` — first real deploy with the full site on devnet.
4. `bun run deploy:mainnet:mutable` — first mainnet deploy, creates the production chains.
5. Publish the per-deploy content URL until the mutable endpoint resolves reliably.

### Notes on mainnet

The RPC used was `https://arbitrum.drpc.org`; the official `arb1.arbitrum.io` endpoint timed out during the deploy and is not recommended as the default.
